# 0.10.3 安全升级说明

本版本修复 master CI 检出的 HTTP/2 依赖漏洞，推荐已有 v0.10.2 部署升级。配套管理后台仍为 v0.10.1。

## API 变更

没有改变正式接口路径、权限策略、请求和响应字段或错误码，继续支持管理后台 `>=0.10.0 <0.11.0`。升级 `golang.org/x/net` 至 v0.60.0 及其必要依赖，修复 GO-2026-6617、GO-2026-6612、GO-2026-6611、GO-2026-6610、GO-2026-6603。

## 数据库迁移

迁移文件与 v0.10.2 相同，不新增迁移或数据转换。已有部署检查 migration 状态，不重建业务库；首次安装沿用完整迁移和初始化流程。

## 配置与队列

源码构建要求 Go >= 1.27.2，以包含对应标准库安全修复。无需变更业务配置、任务载荷和队列名；生产环境继续关闭 debug。service、worker 和 cron 使用同一后端版本。

## 升级顺序

备份配置、数据库和存储，核对前后端兼容范围及 migration 状态。停止旧进程，替换经过校验和核对的 v0.10.3 安装包，再启动 service、worker 和 cron，并验证管理后台 v0.10.1。源码部署使用 Go >= 1.27.2 重新构建。只在已授权目标环境执行写库命令。

## 回滚限制

没有新的数据库迁移，但回退至 v0.10.2 会重新引入本次修复的 HTTP/2 漏洞。保留安装包和配置以应对故障，优先修复前进；不得通过重建业务库或改写已发布 Tag 回退。

## 验证

执行 govulncheck、依赖完整性、Go 全量测试与 vet，核对生成文档、迁移完整性和发布版本身份。master 与 Release 均执行可达漏洞扫描，扫描失败阻止后续发布。目标部署还需验证登录、续期、权限、文件、短信、队列、cron 和健康检查。
