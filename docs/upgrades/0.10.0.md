# 0.10.0 首次安装与发布说明

本版本是公开候选；没有已发布的升级基线。`docs/release.json` 的 `previousTag: null` 仅用于首次发布。正式 Tag 后必须指向真实上一版本，禁止修改已发布迁移。

## API 变更

提供个人工作台、个人请求日志、待办、文件、短信、任务和权限 API；完整业务目录和示例在本 Tag 的 `docs/api-documentation.json`，由 `docs/api/` 源文件生成；官网版本选择读取该 Tag 的提交。以本 Tag 的 `docs/openapi.yaml`、错误码文档及前端请求为准。当前 OpenAPI 自动生成范围是路由、方法和安全策略，未完整覆盖业务请求/响应 schema。发布前人工核对参数必填性、响应字段、错误码、OTP/会话、菜单权限码与分页语义，不以路由检查通过代替业务兼容验证。前端支持范围见 `docs/release.json`。

## 数据库迁移

新安装执行完整 migration；不承诺未发布 0.9.x 开发数据库原地升级。已有真实业务数据时禁止用 `init-system` 作为升级手段；必须先提供独立成对迁移及数据转换方案。首次正式发布后，所有已发布迁移不可更改或删除。

## 配置与队列

按本版本配置样例核对 JWT、凭证加密密钥、存储、Redis、队列和短信配置。`service`、`worker`、`cron` 使用同一后端版本；首版保持单 cron。密钥变化、任务载荷变化和非幂等任务需要明确停机、排空或重试限制。

## 升级顺序

首次安装：准备配置和独立数据库，执行迁移、初始化及 API/任务元数据同步，再启动 worker、cron、service 和兼容前端。存在业务数据的升级：备份数据库/配置/存储，先评估旧服务是否兼容新结构，必要时维护窗口停服务，执行新增迁移，再同步路由/任务和部署后端及配套前端。写库命令只在明确授权的目标环境运行。

## 回滚限制

静态前端和二进制可回退到兼容版本；数据库 down 不保证恢复已丢失数据。结构、密钥、权限或任务格式不兼容时，不允许只回退二进制。必须准备数据库/存储备份恢复或向前修复，并明确停机与数据损失窗口。

## 验证

发布检查、生成文档漂移、迁移校验、专用测试库业务回归及前端构建/浏览器场景均为必需。目标环境另验证登录/续期/权限、资料 OTP、文件上传与私有预览、待办、队列/cron、审计和健康检查；仓库测试不能替代目标环境验收。
