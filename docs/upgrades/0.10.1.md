# 0.10.1 发布与部署说明

`v0.10.0` Tag 的发布校验失败，未生成正式发行产物。本版本保留该 Tag 作为代码比较基线，以 `v0.10.1` 提供经校验的安装包。首次部署仍参考 `0.10.0.md` 的初始化要求。

## API 变更

本版本没有修改接口路径、权限策略、请求和响应业务字段、错误码或数据库迁移。控制器测试改用独立配置和注入的真实本地存储驱动，避免依赖开发者数据库。后端仍支持管理后台 `>=0.10.0 <0.11.0`，推荐配套正式发布的 `v0.10.1`。

## 数据库迁移

迁移文件与 v0.10.0 完全相同。已有源码部署只需核对 migration 状态；新安装按 `0.10.0.md` 执行初始化。不要修改已发布迁移或使用 `init-system` 清空已有业务数据库。

## 配置与队列

配置结构、密钥要求、队列名和任务载荷保持不变。保留现有部署配置，service、worker 和 cron 使用同一后端版本。

## 升级顺序

核对前后端双向兼容范围，备份数据库与配置，按首次部署说明准备服务、worker 和 cron。已有 v0.10.0 源码部署可替换为 v0.10.1 安装包，使用迁移检查确认状态；本版本没有新增迁移，不重建数据库。

## 回滚限制

保留部署前的代码与配置备份。v0.10.0 没有正式安装包，不依赖其 Release 进行回滚。回退前仍需核对数据库迁移状态和管理后台兼容范围，不能通过改写旧 Tag 或清空数据库回退。

## 验证

干净环境执行控制器测试、Go 单元测试和 vet，再执行专用测试库接口回归、OpenAPI 与错误码生成校验、迁移检查和发布安装包检查。安装包版本及 commit 应对应 v0.10.1；CI 通过不等同于目标环境联调完成。
