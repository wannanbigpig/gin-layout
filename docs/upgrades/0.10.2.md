# 0.10.2 发布与部署说明

后端 v0.10.0、v0.10.1 的发布校验未全部通过，没有正式安装包。保留这些 Tag 作为代码比较基线，本版本提供经完整发布校验的安装包，推荐配套已发布的管理后台 v0.10.1。

## API 变更

本版本没有改变正式接口路径、权限策略、请求和响应字段或错误码，仍支持管理后台 `>=0.10.0 <0.11.0`。仅将 Release 生成的专用测试配置设为 `debug: true`，与测试样例一致，覆盖 demo 路由；正式 API 文档仍排除调试路由。

## 数据库迁移

迁移文件与 v0.10.0 完全相同。新安装在独立数据库执行完整迁移及初始化；已有源码部署核对 migration 状态，不新增迁移、不重建业务库。已发布迁移禁止改写。

## 配置与队列

保留现有 JWT、凭证加密、存储、Redis、短信和队列配置。service、worker 和 cron 使用同一后端版本；任务载荷和队列名没有变化。生产部署使用自己的配置，关闭 debug；CI 配置仅用于专用测试库。

## 升级顺序

备份数据库、配置和存储，核对前后端双向兼容范围。首次安装先执行迁移和初始化、同步 API 与任务定义，再启动后端进程及管理后台。已有部署检查迁移状态后替换后端安装包，再验证管理后台 v0.10.1；写库命令只在已授权目标环境执行。

## 回滚限制

保留实际部署过的代码或安装包及对应配置。旧后端 Tag 没有正式安装包，不依赖其 Release 回滚；回退前核对迁移状态和前端兼容范围。不得通过清空业务库或改写旧 Tag 回退。

## 验证

验证 Go 单元测试和 vet、专用测试库接口回归、生成文档漂移、迁移完整性及多平台安装包。核对版本 v0.10.2 与 Tag commit；目标部署还需验证登录、续期、权限、文件、队列、cron 和健康检查。
