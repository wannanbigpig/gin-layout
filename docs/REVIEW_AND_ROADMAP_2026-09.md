# 2026-09 全仓审查修复与产品方向

范围：`gin-layout` 与配套 `x-l-admin-vue3`。本次包含代码修复、回归测试、接口契约对齐和产品方向评估。新增产品功能仍属于建议，未视为全部开发需求。

## 架构判断

保留现有 Gin/controller/service/model/resource 分层、声明式 Catalog、数据库关系驱动权限，以及 service/worker/cron 三类进程。当前主要问题在事务、凭证信任、缓存失效和生命周期边界，不需要通过引入 Repository、DDD 或微服务解决。

多 API 实例共用 MySQL、Redis 和一致配置；权限策略和全局版本在同一 MySQL 事务提交。请求优先读取 Redis 版本，dirty、缓存缺失或 Redis 异常时回源 MySQL，并在本机用 `singleflight` 合并并发回源。权限提交仍通过 Redis 通知其他实例立即刷新，30 秒版本安全过期和定时回源补偿异常窗口。版本读取或策略加载失败时拒绝判权。正常路径为近实时，Redis 在权限写入窗口不可用时仍可能存在最多约一个版本 TTL 的旧值窗口，因此不表述为跨实例强一致。

文件部署采用单实例 local、多实例对象存储。当前内置云驱动为阿里云 OSS；其他兼容方案需实现现有 Driver 契约。共享卷没有纳入本轮部署方案。API Pod 使用相同 JWT 密钥；LB/K8s 需配置可信代理、WebSocket 转发和 readiness。代码级能力与本地多进程验证不等于已完成真实 K8s/OSS 部署验收。

## 数据变更日志

复用现有 `request_logs.change_diff`，无需增加一套重复日志表。账号、配置、产品和文件操作补充字段差异或动作结果；提供“仅有数据变更”的列表和导出筛选。密码、token、存储 secret 不记录明文，密钥修改仅记录变更标记。

日志以应用请求为入口，包含操作者、请求标识、操作结果及适用的变更内容。它不是数据库 CDC：人工 SQL、其他应用直接写库不自动纳入。异步队列和内存 fallback 支持正常关闭排空，但不承诺断电、强制杀进程时零丢失。若未来需要不可篡改与零丢失审计，应另行评估事务 outbox、归档与外部不可变存储。

沿用现有 GORM、Casbin、go-redis、Gorilla、Asynq、OSS SDK 和前端组件生态，按实际调用路径修复使用问题，不为消除工具提示盲目替换依赖。

## 产品方向：建议，未全部实施

产品定位建议为：**面向后台与内部系统的 Gin 应用框架，提供 Laravel 式的约定、工具链和开箱即用体验，并附带可运营的 Admin 管理套件。** 不追求 Laravel API 兼容或逐项复刻；核心价值是缩短“定义业务数据 → 生成可上线管理模块”的路径。

建议保持三层边界：配置、迁移、路由、验证、响应、缓存、队列等属于框架基础；认证、权限、DataScope、审计、文件、任务、导出、通知和 Dashboard 属于可组合 Admin 套件；Product 属于可整体替换的参考业务，平台基础不能反向依赖它。

| 阶段 | 框架产品重点 | 验收结果 |
| --- | --- | --- |
| P0 | 单一 `ModuleSpec` 驱动 migration/model/form/service/resource/Catalog/权限/菜单/审计/测试/OpenAPI/前端类型；修正 Generator 中不安全的 `Save`、吞错和事务外权限模板；建立初始化到首个模块的黄金路径 | 干净环境按一份文档可初始化并生成可编译、可测试、可授权、可审计的业务模块 |
| P1 | 通用导入生命周期、结构化实体审计索引、S3 兼容存储、按角色裁剪 Dashboard，并把 Product 完成到参考级模块 | 单条业务记录可追溯，导入可预检和幂等，local/对象存储部署均有可验证路径 |
| P2 | 可选 TOTP MFA、服务账号/API Key、SMTP/Webhook 通知、OpenTelemetry 和通用批量操作 | 功能关闭时不增加部署依赖，启用时具备管理入口、权限、审计和失效机制 |

多租户模型、库存/订单/支付、CRM/HRM/CMS、通用 BPM、低代码、微服务治理和分布式事务不进入默认 Core；这些能力会迫使多数使用方接受特定领域模型，适合作为独立模块或生态扩展。

产品模块适合定位为“可替换的参考级业务模块”：展示后台脚手架怎样组合数据权限、文件、字典、任务和审计。平台基础模块不能反向依赖产品模块，项目不默认演变为 ERP 或电商系统。

| 阶段 | 建议 | 边界 |
| --- | --- | --- |
| P1 | 通用产品档案：系统生成稳定编码、树形分类、单位、封面/附件、详情、审计、异步导出 | 单位复用字典，分类独立树表；复用文件引用、DataScope、任务与导出中心 |
| P2 | 通用导入中心 | 模板版本、预检、确认提交、错误文件、幂等；先仅支持创建，禁止默认覆盖 |
| P2 | 批量启停/转部门，通用记录变更历史入口 | 每一批次继续执行权限校验；历史查询需补结构化实体维度 |
| P3 | SKU、库存、供应商、价格体系 | 属于行业扩展，需独立业务目标；不自动加入主仓 |

首期产品档案建议保持 API 价格整数分。若页面改为元输入，需精确转换并明确币种；本轮缺陷修复不擅自改变已有价格契约。封面与附件只接收文件 UUID，校验引用权限并事务维护引用。异步导出由 worker 重新确认触发用户和 DataScope，结果保持私有，CSV 防公式注入，不导出临时签名 URL。

单位可复用字典；分类按已确认的树形需求独立建模，并处理父子关系、移动防环及引用删除保护。后端已评估 FileReference、DataScope、change_diff 和异步 CSV 的复用方式；前端已有表格、部门树、字典选项、FilePicker、按钮权限、提交锁和导出提交器可复用。

已确认首期采用树形分类，产品编码由系统生成。编码生成必须适用于多实例并发，并由数据库唯一约束保障；创建后保持稳定，避免分类移动或名称修改改变业务标识。具体展示格式与分类接口、迁移设计在实施方案中收敛。该决定替代此前的平面分类与业务方手填编码建议；其余路线仍为建议，当前未新增这些字段、模块和接口。

## 2026-09-16 实时权限同步复核

本地两个独立 Go 进程共用测试 MySQL/Redis，执行 3 轮授权和撤权，共 6 次跨进程观测：授权耗时 26.29、24.18、25.22 ms；撤权耗时 23.79、3.75、23.88 ms。计时包含策略写入、本机刷新、通知发布及另一进程观察到新策略，观察端采用 20 ms 检查间隔。每轮使用独立策略并清理；该小样本验证说明当前正常路径即时触发刷新，不构成生产延迟承诺或压力测试。

[Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/#delivery-semantics) 为至多一次投递，断线窗口可丢消息，所以实现已增加持久化权限版本与请求级版本校验，并保留周期回源。Redis 可用时，权限写事务的 dirty 标记会让并发请求等待 MySQL 版本行锁后读取提交或回滚结果；Redis 在写入窗口不可用时，30 秒版本安全过期限定旧缓存窗口。当前仍没有“所有实例已刷新”的确认屏障，因此属于近实时和有界最终一致，而非强一致广播。
